# Projects

Ten portfolio-grade projects, each specced to portfolio depth. Build these to consolidate the curriculum into a demonstrable portfolio.

## How to use these projects

1. Read [how to pick a project](01-how-to-pick.md) (coming soon; for now, read the project descriptions and pick the one that excites you).
2. Read the project spec carefully. It defines the problem, the architecture, the stack, the eval rubric, and the stretch goals.
3. Build the project. Use the curriculum as reference. Do not look at the reference solution until you have a working version of your own.
4. Run the eval rubric against your implementation. Iterate until you meet the targets.
5. Write a README for your implementation. Document the architecture, the eval results, and the trade-offs you made.
6. Deploy the project. A deployed project is worth 10x a local one in a portfolio.

## Difficulty guide

- ⭐⭐ (2 stars): 1-2 weeks for a learner who has finished modules 01-03.
- ⭐⭐⭐ (3 stars): 2-3 weeks for a learner who has finished modules 01-05.
- ⭐⭐⭐⭐ (4 stars): 3-4 weeks for a learner who has finished modules 01-07.
- ⭐⭐⭐⭐⭐ (5 stars): 4-6 weeks for a learner who has finished the full curriculum.

## Reference solutions

Reference solutions live in [projects/-solutions/](-solutions/) (coming soon). They are gated behind a spoiler warning: do not look at them until you have a working implementation of your own. The learning is in the building, not in the reading.

## Contributing a solution

If you build a project and want to contribute your solution as the reference, open a PR. The bar: the solution passes the eval rubric, is deployed (or deployable), and has a clear README. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the full process.
